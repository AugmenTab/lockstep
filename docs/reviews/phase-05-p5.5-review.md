# Phase 5 / P5.5–P5.7: independent review of capsule mode, and dispositions

- **Reviewed:** the helper's capsule mode (`scripts/capsule/helper-capsule.sh`, `control-helper`), the runtime's
  exchange operations (push, exec-argv, pull, tar checks), `answer`, the preflight, the service's capsule adapter,
  and `check-capsule-runner`.
- **Reviewer:** an independent, read-only agent; it ran nothing. **Dispositions:** the Implementer.

| # | Sev | Finding | Disposition |
|---|---|---|---|
| 1 | HIGH | Read-only roles worked in the Implementer's live VM: their instructions, the code they read and their answer passed through a guest an Implementer controls. A lingering root process could forge a reviewer's "approve". | **Fixed.** (a) The answer never touches a guest: the bridge (trusted, in the provider's container) writes it straight to the run's host `/output`, mounted for the purpose. (b) Reads of `/input/*` are served from the host's read-only copy. (c) Read-only live roles run in the **verification capsule**, restored from its trusted snapshot and given exactly the Supervisor's tree; with no verification capsule they are refused. New checks **E1** (a planted forger in the Implementer's VM cannot change the reviewer's answer; the role reads the Supervisor's own instructions) and **C3** (the role ran in the verification capsule). |
| 2 | MED | The `.gitignore` filter made push and pull inexact: verification could miss tracked-but-ignored files, and size-and-time matching could keep a stale guest copy. | **Fixed for verification and review:** `push … exact` empties `/work/tree` and extracts the Supervisor's tree with no filter (check **E2**). The Engineer's pushes keep ignored build output but compare by checksum. **Remaining:** on pull, a tracked-but-ignored file is missing from the returned tree, which can make a correct implementation look out of scope. This **fails closed** (a spurious refusal, never a false accept) and is recorded as a limitation. |
| 3 | MED | Capsule runs had no host-side deadline; cancel did nothing; a cancelled run's tree was still pulled. | **Fixed.** `exec-argv` keeps its own host deadline (limit + 60 s) and watches `.capsule-out/.cancel`. On either, it kills the transport and force-stops the VM (its disk and caches are kept; a verification VM is restored before every use anyway); the helper starts it again. `cancel-run` writes the cancel file. Only a run that ended by itself is collected. Check **E3**. |
| 4 | MED | Guest streams were written to host files with no cap. | **Fixed.** stdout and stderr are capped at 8 MiB + 1 in the pipeline; pulls at 4 GiB + 1 before the size check; serve's raw answer at 4 MiB + 1. |
| 5 | MED | `tar_safe` did not check sizes, modes or hard links. | **Fixed.** Per-entry 1 GiB and total 4 GiB limits on the declared sizes (sparse ones included); `link to` / `->` entries refused; after extraction `chmod -R u+rwX,go-w`. Check **E4** (a symbolic link: the tree is refused and the Supervisor's left unchanged). A hard-link fixture is not yet written. |
| 6 | MED | A broken capsule configuration silently fell back to Phase 4 containers; a stale `runner/capsule` could survive. | **Fixed.** `DIR/capsule` present but unusable gives **capsule mode UNAVAILABLE**: every run is refused (`capsule-mode-unavailable`). `control-helper` removes `runner/capsule` itself. Check **E6**. |
| 7 | LOW | A protected-file restore failure was silent. | **Fixed.** The run fails (`launch-failed`) and the Supervisor's tree is left as it was. |
| 8 | LOW | `capsule_live_refusal` matched tokens by position; several flags were not blocked. | **Fixed.** Exactly one `--tools` with an empty value is required; `--plugin-dir`, `--plugin-url`, `--agent(s)`, `--allowedTools`, `--bare`, `--ide` and `--chrome` are refused too. |
| 9 | LOW | A VM that went away during a run was reported as the program's exit. | **Fixed.** `exec-argv` answers `unavailable reason=vm-stopped-during-run`, and the helper reports `launch-failed`, never an exit status. |
| 10 | LOW | Preflight could pass on stale probe output. | **Fixed.** Output is deleted before each probe, and an incomplete probe fails `guest-probe`. |
| 11 | LOW | Stale bind locks or open bindings could block forever. | **Fixed.** A bind lock whose holder is dead is removed. A helper starting in capsule mode closes the project's invocations left open by a helper that stopped. |
| — | tests | A2/C3 were vacuous for the guest side; C2's credential grep matched any missing file; several cases were untested. | C2 now asserts a specific `auth-absent-in-capsule` line. C3 asserts the verification capsule. E1–E6 were added. Not yet added: hard-link and mode-000 fixtures, and a guest-side check of `/work/tree` after a read-only run. |
