# Phase 5 update 1: independent review and dispositions

- **Reviewed:** everything since `0ef0227`. That covers the D4 enforcement (`hostLoopback`), `reconfigure`,
  template currency, the preflight exposure checks, the operator status and stop control, P5.8 (`CapsuleGitTest`),
  P5.9 (`check-capsule-recovery`) and P5.11 (`check-capsule-e2e`).
- **Reviewer:** an independent read-only agent (ran nothing). **Dispositions:** the Implementer.

| # | Sev | Finding | Disposition |
|---|---|---|---|
| H1 | HIGH | Preflight's exposure check used unprivileged `lsof`, which sees only the caller's processes, and TCP only. Root and launchd listeners (SSH 22, Screen Sharing 5900, SMB 445) were invisible. | **Fixed.** `netstat -anv -p tcp\|udp` lists every socket on the host whoever owns it. TCP listeners and bound UDP sockets beyond loopback are named, with `--allow-lan` and `--allow-lan-udp` as the owner's explicit acceptance. Confirmed on this Mac: netstat shows a launchd listener `lsof` did not. |
| H2 | HIGH | P5.9's "nothing of its tree came back" was vacuous: the files were written only after the sleep the test interrupts. | **Fixed.** Each run writes a marker **before** the interruption (`sync`ed), and the check asserts that marker is not in the Supervisor's tree. |
| M1 | MED | A capsule from an older template was still used by the helper (template currency was only displayed). `reconfigure` would report a base-image change as current. | **Fixed.** The helper refuses a stale capsule (capsule mode unavailable, with the reason). `reconfigure` refuses when the template's `images:` differs from the capsule's (`base-image-changed-reprovision-required`): a new base image needs a new disk, which is an operator decision for a non-disposable capsule. |
| M2 | MED | `snapshot` and `restore` restarted the VM without the configuration audit, and so did `start` on an already-running VM. | **Fixed.** Every `limactl start` the runtime makes is preceded by `audit_vm`. `start` audits a running VM too, and refuses on drift. |
| M3 | MED | A cancel or helper stop during the verification restore was lost; the run went on to its wall limit. | **Fixed.** `.capsule-out` is made and the status published before the restore. `.cancelled` is checked before the push and before `exec-argv`; a cancelled run never starts its program. |
| M4 | MED | Only a graceful helper stop was tested; after `kill -9` an orphaned run subshell could still bring a tree back. | **Fixed.** Each capsule run records its process id. A starting helper ends any orphaned capsule run before it answers that run `interrupted`: it kills the recorded process, only while that process is still a helper's, and cancels the guest program through the runtime's cancel file. New check **R1b** (`kill -9` mid-run). The first version of this fix broke every capsule run; see below. |
| M5 | MED | The status and the stop control were not tied to a project. | **Fixed.** The capsule config's optional `lockstep-project ID` line flows into the status file (`project`). The section is shown, and a stop accepted, only on that project's page. |
| L1 | LOW | `sendCancel` hid send failures. | **Fixed.** `requestCancel`; a failed send says nothing was stopped. |
| L2 | LOW | Preflight's isolation grep was weaker than the runtime's check. | Accepted: `capsule-healthy` requires the runtime's `audit=ok`, which runs the full `host_loopback_off` check. The grep is only a named report line. |
| L3 | LOW | The `true` branch of the check was never exercised; preflight did not see the reversed case; there was no negative control. | **Fixed.** D4.8 now has three cases. Reversed in config and record together, it is refused by the setting's own check. Preflight refuses the reversed setting. **Control:** with the setting removed (started with `limactl` directly, test only) the guest **does** reach the host's loopback. |
| L4 | LOW | P5.11 does not use the live path and does not drive the capsule section in the browser. | Recorded as a limitation. The live path is qualified separately: `check-capsule-runner` C2/C3/E1 use the real CLI, bridge, `serve` and invocations. Brigid is that path's first live use. |
| L5 | LOW | The `CapsuleGitTest` control's trigger sits in the worktree; the test goes straight to `GitSupervisor`; `setEnv`. | Accepted with notes. The Supervisor never uses a worktree: it commits through plumbing from the returned files. That a hostile `.gitattributes` is committed as bytes, with no filter run, is the point. Capsule transport to the tree is E4/E5. Tasty runs the suite sequentially. |
| L6 | LOW | `reconfigure` is not serialised against an active run. | Documented: preflight tells the operator to reconfigure while Lockstep is idle. `reconfigure` stops the VM, so a running step would end as `launch-failed` (never as an exit). |

## Found while qualifying the fixes

| # | Defect | Effect | Fix and check |
|---|---|---|---|
| Q1 | The M4 fix recorded the run's process id with `$BASHPID`. macOS's `/bin/bash` is 3.2, which has no `BASHPID`, and the helper runs under `set -u`. | Every capsule run's subshell died right after its journal `start` and never answered. The engine reported `helper-no-result`, and each check waited out the full 1800 s command limit. | `self_pid` (the parent of a child `sh`), checked against `$!` on bash 3.2. |
| Q2 | When a run's process exited without answering, the helper cleared its slot and said nothing. | Any fault in the run code (Q1 was one) cost the whole command limit before anyone could see it. | The helper answers that run `interrupted` at once (never replayed), cancels its guest program, and records the failure in the operator's status. New check **A4**: the run's process is killed mid-run; the answer came in under 1 s, its tree did not come back, no `exec-argv` was left, and the next run worked. |
| Q3 | A cancelled or orphaned run leaves the capsule stopped (the runtime stops it), and the Engineer's next run did not start it. | After R1b, the next run failed at the push (`launch-failed`) until something else restarted the VM. | The helper starts a stopped Engineer's capsule before the push (audited, as every start is). The recovery check now starts the VM before looking inside it, clears its markers first, and keeps each run's runtime log. |
| Q4 | The P5.11 browser journey reloaded the page a fixed number of times (120 × about 10 s), with no way to stop early. | A green run took 25 minutes, 20 of them after the transaction was already done. | `pollTask` opens the page afresh and stops at the first try that shows the text. |
