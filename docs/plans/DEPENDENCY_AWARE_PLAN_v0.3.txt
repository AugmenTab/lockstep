1. Strategic intent and current frontier
Do not change direction again. Deliver one usable local command
pane and make the first genuinely autonomous single-repository
engineering transaction work as soon as its non-negotiable
dependencies are met. This is not permission to bypass the human/
agent privilege boundary, objective verification, frozen tests, or
recovery.

The current sequence is intentionally UI-first but thin, with vertical
demonstrations throughout. The entire future UI does not need to be
perfected before testing useful local workflows, but unfinished
required Gate C-UX acceptance criteria must be recorded explicitly
rather than silently waived.

Known evidence at time of planning: Gate A human acceptance
recorded previously; Phase 2 P2.1–P2.9 engineering work has been
accepted by the human owner. Gate B machine evidence is recorded in
its r2 report at tested commit 6ba66f5, while the owner’s Gate B
browser walkthrough is NOT_RUN / DEFERRED. Gate B is not
retrospectively marked fully passed. The Implementer has requested
and received authorization for the P3.1 amended trust model; a formal
P3.1 Contract and real implementation must still be proven by their
own receipts. This plan does not assert subsequent work is completed.

Exit priorities:

 1. One command opens a secure UI even when the DB is not ready.
 2. The UI can bring the installation to a safe state and organize one
    local project and task.
 3. The UI can show real status, evidence, and supported human
    decisions.
 4. A bounded Planner → test freeze → one Implementer → verification
    → independent Reviewer → Supervisor Git commit loop operates
    locally in that project.
 5. Only then broaden multi-project, PR, tracker, skills, Red Team and
    unattended features.
1.1 Non-negotiable execution protocol

 • One code-writing Implementer for a repository at any instant. No
   write swarms, even when a DAG shows possible independence;
   read-only independent review or bounded internal advice is
   permitted only within explicit permissions.
 • Every behavior-changing increment: source-linked Contract,
   correctly exercised test setup, baseline classification, required pre-
   freeze semantic challenge, freeze, single writer, deterministic
   checks, independent semantic review, bounded retries, Supervisor-
   owned accepted Git commit. Legitimate document-only changes
   follow an explicitly evidence-bearing non-code exception, never
   fake red tests.
 • An agent cannot create additional authority with its words.
   Supervisor validates scopes and frozen artifacts; unknown side
   effects halt for reconciliation; human signoff remains exact and
   revocable within recorded policy.
 • Tests are model-free by default, and integrated with real
   PostgreSQL/processes/Git where those boundaries are what the test
   claims to prove. Live CLI sessions require separate human
   authorization and bounded resources.
 • No privileged web command runner. Every management action
   must originate in an authenticated, typed, allowlisted, auditable
   capability channel.
 • Every completed sub-phase leaves the application in a buildable
   green state, with actual evidence and a continued normal launch
   path.
 • Use one retrospective per actual development phase (for current
   work, .local/retros/retro-03.md); do not fabricate approvals or
   backdate test evidence.

4.1 P3.1 architectural boundary is fixed

The approved plan is not permission to add a general-purpose
privilege service. The app-facing pane may be containerized; the per-
user host helper has an allowlisted, versioned typed protocol,
authenticated peers, request IDs, replay resistance, exclusive operation
locking, constrained args/paths and durable records. The control pane
has no Docker socket and no unrestricted DB credentials. Bootstrap
sign-in uses a single-use fragment and an explicitly supplied non-
cookie header credential. A strong CSP and escaping tests are
necessary, but do not prove XSS impossible. Old Phase 1/2 cookie routes
remain temporarily with their previously documented limitation; new
protected management routes may not reuse their port-shared cookie.

Until their exact frozen amendments are approved, preserve existing
scripts/service, scripts/lockstep, browser security tests and B1
scripts. The new root launcher is separate. A missing database is a
normal diagnosable state, not a reason to use unauthenticated routes.


4.2 Gate C-UX report package

Must include selected tested Git commit, branch, artifact digests, exact
operator install/binary/schema identity, model-free tests, browser
reports and refusal cases, historical Gate B browser test separately
marked, usability participant evidence (if actually performed), and
open limitations. The owner alone accepts C-UX. Automation passing
cannot manufacture human observations.
